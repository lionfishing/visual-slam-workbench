# ROS 2 节点重构说明

本轮保留现有话题、参数、20ms 同步门限、位姿方向和 Summary 语义，把大 `main` 和长捕获列表整理成两个由类持有状态的节点。

## 接收节点

`RgbdSlamNode` 管理核心、订阅对象、同步器、发布者和定时器。所有回调通过单线程 executor 执行。`ProcessingStats` 保存统计；`FinishState` 保存单次播放的结束协议；`FrameCache` 保存最新输入及最后处理记录。

| 函数 | 职责 |
| --- | --- |
| `validate_slam_parameters` | 校验超时和两个文件路径，文件系统错误通过错误码处理 |
| `is_valid_rgbd_pair` | 检查非空、尺寸及像素类型 |
| `make_pose_message` | 将 `T_wc` 和调用者提供的消息头转换为 `PoseStamped` |
| `configure_subscriptions` | 设置输入统计、近似同步及结束通知订阅 |
| `process_pair` | 共享转换、检查图像、调用核心、按状态发布、更新处理统计 |
| `publish_pose` | 求逆并发布地图中的相机位姿，保持 RGB 采集时间 |
| `handle_playback_finished` | 接受首次通知，忽略重复通知 |
| `inputs_complete` | 超额失败、不足限时等待、等量继续 |
| `tail_is_valid` | 判断显式尾帧是否新鲜、唯一且满足时间门限 |
| `check_finish` | 驱动一次收尾并决定退出 |
| `shutdown_slam` / `print_summary` | spin 返回后的核心结束请求和统计输出 |

`main` 只负责 ROS 初始化、创建节点、spin、异常兜底和退出处理。`cv_bridge::Exception` 保留具体转换错误，其他标准异常转换为失败退出；不再将处理异常漏到 executor 外。非有限位姿不会发布。

## 播放器

`DatasetPlayerNode` 持有播放参数、关联记录、索引和发布者。`tick` 只选择等待、发送下一帧、结束三种动作。

- `load_associations`：统一处理首行和后续行，接受前导空白/注释，报告行号。
- `make_header`：校验十进制整数秒和六位微秒，使用整数解析，拒绝字符错误与秒范围溢出。
- `make_image_message`：统一构造图像消息，处理非连续矩阵及主机字节序。
- `make_camera_info`：集中保存当前 Freiburg 1 标定。
- `publish_frame`：读图、检查类型/分辨率、发布消息并推进索引。
- `finish_playback`：发布实际数量并等待三路传输确认。

时间戳错误不再因 `stoi/stoul` 异常导致未处理终止；非法输入统一返回 1。播放器显式拒绝与固定标定不一致的尺寸。新逻辑没有承诺支持所有 TUM 相机。

## 验证原则

测试针对对外行为：真实输入的配对、输出消息、错误退出码、重复通知截止时间和退出调用，而不是断言私有方法的实现步骤。每次结果保留配置、源码指纹和完整进程输出。

重构不解决上游线程 join、业务队列背压或最终轨迹一致性。这些需要单独设计和验收，不能用本轮正常退出代替。

## 离线评估

`trajectory_eval.py` 分离为轨迹加载、时间关联、刚体对齐、误差计算、报告生成、绘图和 CLI 调度。`Evaluation` 保存中间结果，便于分别验证数学部分与文件输出。关联仍是逐估计帧的最近真值匹配，允许真值复用；镜像修正和不缩放的口径不变。

新增加了重合/共线位置的拒绝，避免为无法唯一确定的旋转生成看似有效的结果。对现有真实轨迹重跑后，整个数值 JSON 报告与重构前完全一致：790 对、ATE RMSE 0.010364941318282897m。这属于历史离线轨迹回归，不是本次 ROS 在线轨迹精度评估。
