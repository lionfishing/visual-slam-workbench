# 第四个项目：ROS 2 RGB-D 视觉定位、建图与评估系统

设计日期：2026-10-10。更新：2026-10-21。状态：完成本机固定版本构建、离线 RGB-D 基线和位置 ATE 工具；已实现 ROS 2 播放、近似同步、核心调用、位姿发布及异常收尾。两个节点完成类和函数整理，32 项自动验证通过，其中包括单次 792 对慢速完整序列。验收证据与限制见 [验证记录](VALIDATION.md)。M2 的业务队列、实时模式、仿真时钟、rosbag2 与严格退出同步仍未完成，RPE、重复实验和点云仍待后续实施。

## 目标与定位

面向 SLAM、机器人感知与机器人软件实习，基于 ORB-SLAM3 建立可复现的 ROS 2 视觉 SLAM 系统，并独立完成数据接口、状态诊断、轨迹评估和点云建图模块。

已有基础：C++ 单目 VO、Python ORB/RANSAC 对照实验、YOLOv8 目标选择与关联。新项目重点补足关键帧、局部优化、回环、重定位、ROS 2 数据流和完整实验能力。

第一版以公开 RGB-D 数据集为输入，不依赖购买传感器。完整 SLAM 核心来自上游；个人实现和第三方能力分别记录。算法扩展在基线与工程版本通过验收后选择。

## 技术决策

| 部分 | 选择与理由 |
| --- | --- |
| 平台 | 沿用 Ubuntu 22.04、ROS 2 Humble，不为项目更换系统 |
| SLAM 核心 | ORB-SLAM3，固定源码提交；先独立示例，后 ROS 2 |
| 主要语言 | 自写模块采用 C++17；实验与绘图使用 Python |
| 首期输入 | TUM RGB-D，一个短静态序列起步，逐步扩展 |
| ROS 接口 | 自建薄封装；借鉴第三方时标明来源与具体复用范围 |
| 可视化 | RViz2；Pangolin 仅按核心依赖与调试需要配置 |
| 评估 | evo 或官方评估工具，固定版本及评估参数 |
| 点云 | 关键帧深度投影、无效深度过滤、体素降采样、PCD 导出 |
| 深度学习 | 第一版不依赖 YOLO；保留既有视觉环境，后续按需使用 |

官方 ORB-SLAM3 ROS 示例面向 ROS Melodic，不是 ROS 2 Humble 节点。Ubuntu 22.04 的普通 RGB-D 示例已在本机固定版本构建并运行，ROS 2 接口仍需自行开发与验证。

## 第一版数据流

```text
TUM RGB-D 图像、深度、时间戳、标定
                 |
        dataset_player（自写）
                 |
      RGB / Depth / CameraInfo
                 |
       slam_ros2（自写封装）
                 |
      ORB-SLAM3 核心（上游）
          /      |       \
     位姿/轨迹  状态诊断  关键帧图像、深度及位姿
         |       |              |
       RViz2   CSV 日志     mapping（自写）
         |                      |
     轨迹导出                点云 / PCD
         |
   离线评估与结果汇总（自写实验流程）
```

关键帧数据接口在阅读上游后确定，必要时做范围明确的补丁。第一版没有机器人底盘，不凭空发布 base_link 外参，不伪造协方差，也不把稀疏点地图直接称为可导航地图。

## 里程碑与验收

按每周约 8–12 小时，初步预估 12–16 周完成可展示版本；进度按验收调整。

### M0：项目准备（约 1 周）

- 检查依赖和上游构建要求，固定 ORB-SLAM3 与 Pangolin 提交。
- 将上游源码、构建产物和项目安装前缀隔离管理，保留兼容性补丁。
- 选择一个短序列，核对压缩与解压空间、相机参数和深度单位。
- 记录下载地址、校验值、构建命令及依赖版本。

验收：干净构建通过；依赖来源可追踪；不覆盖系统 OpenCV 或系统安装目录。

### M1：离线 SLAM 与基线评估（约 2–3 周）

- 跑通官方 RGB-D 入口，导出最终轨迹。
- 阅读 Tracking、LocalMapping、LoopClosing、KeyFrame 与 MapPoint 的关键调用关系。
- 完成时间戳关联、真值对齐、ATE/RPE 与轨迹图。
- 记录初始化、跟踪失败、重定位、地图重置等状态；需要时添加日志。

验收：至少一个序列端到端复现；逐步扩展至至少三个不同条件的序列，每个重复三次；失败运行也纳入报告。解释一个实际失败案例，而不只展示成功截图。

### M2：ROS 2 集成与诊断（约 3–4 周）

- 实现数据播放节点，保留原始时间戳，发布图像、深度和相机信息。
- 实现 rclcpp SLAM 封装、图像同步、参数配置、launch 文件和正常退出时轨迹保存。
- 定义位姿、轨迹与状态话题，完成 RViz 配置。
- 实现有界输入队列，明确完整处理模式与实时丢帧模式，统计输入帧、处理帧和丢帧数。
- 支持一致的仿真时钟；录制和回放 rosbag2，检查 QoS 与时间戳。

验收：启动命令可复现；同一序列可直接播放和 rosbag2 回放；轨迹与离线基线差异有解释；不会无界积压图像；跟踪失败不继续发布伪装成有效结果的旧位姿。

### M3：关键帧点云建图（约 2–3 周）

- 从深度与相机内参反投影至相机坐标，再转换到地图坐标。
- 实现深度范围、无效值过滤和体素降采样。
- 按关键帧保存局部点云，使用最终优化后的位姿重建离线地图。
- 在线展示先作为预览；明确回环、关键帧剔除与地图重置的处理策略。
- 对比全部采样与降采样的点数、构建耗时、文件大小和内存占用。

验收：PCD 可重新加载，几何尺度和朝向合理；最终地图使用优化后的关键帧位姿；不把相机曾经走过的位置永久拼接成未经回环修正的地图。

### M4：代表作品交付（约 2–3 周，可穿插进行）

- README 说明用途、架构、环境、数据准备和完整复现步骤。
- 输出评估表、轨迹图、失败案例分析和 2–3 分钟演示视频。
- 梳理第三方与个人贡献、已知局限、依赖版本和上游补丁。
- 在重新打开的终端中按文档完整复现一次。

验收：读者能复现至少一个序列；每条性能结论能追踪到配置、提交和结果文件；简历只使用已完成且有证据的数据。

## 实验口径

- ATE：衡量整体轨迹与真值的偏差。RGB-D 主结果使用 SE(3) 刚体对齐，不靠尺度缩放掩盖深度比例问题。
- RPE：衡量相隔一定时间或距离的相对运动误差，明确间隔及平移/旋转单位。
- 有效跟踪比例：明确分母为输入帧还是处理帧；同时报告两者，防止丢帧掩盖失败。
- 轨迹覆盖率：报告参与真值关联的估计帧数和时间范围；较短成功片段不能代表全序列精度。
- 性能：记录硬件、图像分辨率、可视化开关、处理耗时 P50/P95、处理帧率和队列丢帧数。算法处理耗时与端到端延迟分开。
- 在线位姿与最终优化轨迹分别保存，禁止把最终轨迹精度描述为在线性能。
- 多次运行报告中位数、范围及失败次数；新配置在独立序列上验证，避免只调优展示序列。

## 关键工程判断

1. 位姿方向：先核对 API 返回的是 T_cw 还是 T_wc。相机到世界与世界到相机需要求逆，不能直接混用。
2. 坐标系：相机 optical 坐标与常规机器人坐标不同。每个话题明确 frame_id，TF 保持单一父节点与一致时间戳。
3. 深度：确认整数深度缩放、单位、RGB/深度配准与图像缩放后的内参。数值类型正确不等于物理尺度正确。
4. 同步：先按数据集时间戳关联再发布；记录关联误差。回放暂停、倍速和重新开始时应明确节点状态。
5. 回环：全局修正可能引起位姿跳变，不将它误写为连续局部里程计；需要 map/odom 分离时再设计独立连续里程计来源。
6. 地图：关键帧可能剔除，Atlas 可能重置或合并。首期优先完成最终离线地图，在线全局一致地图作为后续工作。

## 后续只选一项扩展

在第一版完成后，根据实验瓶颈选择：

- 动态特征筛选：对比原始、语义筛选、语义加几何判断；静止的人和运动的人不能仅靠类别区分。保留静态序列对照，并统计耗时。
- 跟踪与重定位分析：增加失效诊断，针对模糊、弱纹理、遮挡进行受控实验，提出并验证一个明确改动。
- 视觉惯性扩展：在 RGB-D 与 ROS 2 主线成熟后，用合适的数据集学习 IMU 初始化、时间同步和外参。

Nav2、完整自主导航、从零重写 SLAM 和大型神经模型不列为首期交付要求。

## 环境与资源

依据 ../../../ENVIRONMENT.md 及方案制定时的检查：Ubuntu 22.04.5，Ryzen 7 5800H，约 13GiB 内存，无 Swap，根分区当时可用约 30GiB。

- 编译从两个并行任务起步，实际观察峰值内存。
- 新增源码、构建和数据先按合计不超过约 8–10GiB 规划；实际下载前重新核对，尽量保留至少 15GiB 空间。
- 不重复建立大型 PyTorch 环境；评估 Python 环境保持轻量且独立。
- 报告记录 RTX 3050 与 CUDA 验证通过；当前受限会话 nvidia-smi/PyTorch CUDA 不可用，原因未确定，不据此改驱动。
- 第一版纯视觉核心不依赖 CUDA；图形显示可用性仍需运行验证。

本轮只读检查确认已安装 Eigen、OpenCV、Boost serialization、OpenSSL、GLEW、Mesa GL/EGL、PNG/JPEG 开发包，以及 ROS 2 cv_bridge、message_filters、diagnostic_msgs、tf2_ros、rosbag2。两个常见系统 CMake 目录未找到 Pangolin，libepoxy-dev 未在 dpkg 中查到；是否需要新增该包取决于选择的 Pangolin 版本与构建选项，尚未安装任何依赖。

## 第一轮实施任务

1. 检查项目必需头文件、库及图形依赖，只列出缺项。
2. 获取并审阅固定版本上游源码，选定最小 RGB-D 构建路径。
3. 准备项目内依赖前缀和构建配置，记录必要兼容性修改。
